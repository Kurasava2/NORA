# Карта первичных и производных материалов

> Навигационный слой для различения источников, производных сборок, промежуточных рабочих материалов и визуальных ассетов. Этот файл **не является owner’ом содержательного канона** и не повышает статус перечисленных материалов.

## 1. Первичные источники прозы

Основной источник текста новеллы — отдельные файлы глав в `01 Новелла/Рукопись/`.

Правило:

- литературная правка выполняется в отдельной главе;
- [[../01 Новелла/Сводная рукопись|Сводная рукопись]] не используется для обратного исправления главы;
- `07 Читалка/NORA — Читалка.html` не используется как более высокий источник прозы;
- при выпуске литературного пакета действует [[Порядок выпуска литературного пакета]].

`01 Новелла/Оглавление.md` — навигация по рукописи, а не отдельный источник текста глав.

## 2. Производная сборка рукописи

`01 Новелла/Сводная рукопись.md` — **производное**.

Она собирается скриптом `08 Инструменты/собрать рукопись.py` из отдельных файлов глав первого и второго года. Сам генератор прямо помечает результат:

- `тип: сводная рукопись`;
- `статус: производное`;
- `источник: отдельные файлы глав`.

Следовательно, сводную рукопись не нужно переносить или дробить только из-за большого размера. Её ценность — единая читаемая сборка, а не владение текстом.

## 3. Читалка и её промежуточный слой

`07 Читалка/NORA — Читалка.html` — интерфейсный производный артефакт.

Её правила принадлежат [[../07 Читалка/Правила обновления]]. Источник текста — соответствующая глава после литературного прохода.

`07 Читалка/Разметка/` — промежуточный рабочий слой подготовки читалки. Разметка может иметь собственный статус проверки/утверждения, но **не становится владельцем прозы** и не отменяет соответствующую главу.

Критическое техническое ограничение: ключ `localStorage` `liren-reader-state-v2` не менять без отдельного решения, иначе сбрасывается прогресс читателя.

## 4. Инструменты сборки и проверки

`08 Инструменты/` хранит процедуру и код, а не содержательный канон произведения.

Ключевые файлы:

- [[Порядок выпуска литературного пакета]] — канонический порядок выпуска;
- `собрать рукопись.py` — сборка производной сводной рукописи;
- `проверить проект.py` — структурная проверка числа/нумерации глав, читалки, ключа прогресса, переносимости путей и части устаревших имён/терминов.

Изменение пути производного файла допускается только одновременно с обновлением зависимого кода и последующей проверкой.

## 5. Визуальные материалы

Визуальный слой уже разделён по назначению:

- `06 Визуальный канон/Персонажи/` → [[../06 Визуальный канон/Персонажи/Указатель|визуальный указатель персонажей]];
- `06 Визуальный канон/Мир/` → [[../06 Визуальный канон/Мир/Указатель|визуальный указатель мира]];
- `06 Визуальный канон/Предметы/` → [[../06 Визуальный канон/Предметы/Указатель|визуальный указатель предметов]];
- `06 Визуальный канон/Карты/` → [[../06 Визуальный канон/Карты/Состояние карт|Состояние карт]].

Изображение не получает одинаковый статус только потому, что находится в `06 Визуальный канон`.

Примеры действующего принципа:

- для персонажей текстовый owner имеет приоритет над случайной деталью изображения; конкретные референсы имеют статусы из визуального указателя;
- для предметов утверждённый модельный лист подчинён текстовой геометрии и размерам при расхождении;
- изображения мира не используются для самостоятельного вывода о биологии или сюжете;
- карты в целом имеют статус `на проверке` и не могут отменять текстовый канон до ручной сверки.

## 6. Карты, CSV и расчётные матрицы

`06 Визуальный канон/Карты/` содержит не только изображения, но и реестры городов, матрицы прямых/маршрутных расстояний, SVG и сводные/топонимические/физико-политические варианты.

Эти файлы нельзя механически объявить одним типом «производного канона».

Их использование определяется:

1. [[../06 Визуальный канон/Карты/Состояние карт]];
2. профильным государственным/региональным owner-файлом;
3. статусом соответствующего расчётного слоя.

До завершения ручной проверки карт массовое удаление вариантов и переносы каталогов не выполняются.

## 7. Правило физической миграции

На текущем этапе **не перемещать**:

- `01 Новелла/Сводная рукопись.md`;
- `07 Читалка/NORA — Читалка.html`;
- существующую разметку читалки;
- визуальные карты, CSV-реестры и матрицы;
- уже зарегистрированные визуальные референсы.

Причина не в том, что текущие пути идеальны навсегда, а в том, что GitHub code search сейчас возвращает `incomplete_results: true` и не позволяет надёжно доказать отсутствие входящих ссылок. Нулевой результат такого поиска не является достаточным основанием для физического переноса.

## 8. Когда физическое изменение допустимо

Перенос или удаление производного/визуального файла выполнять только если одновременно выполнены условия:

- найден и проверен его действующий owner/регламент;
- надёжно проверены входящие ссылки и прямые пути;
- обновлены зависимые скрипты/HTML/Markdown-ссылки;
- сохранены пользовательские технические ограничения, включая ключ прогресса читалки;
- после записи выполнена повторная проверка всех затронутых путей.

## Итог Stage 10

Текущая структура уже достаточно хорошо разделяет первичную прозу, производную сводную рукопись, читалку, инструменты и основные классы визуальных материалов. Поэтому структурная нормализация Stage 10 выполняется **через явные границы ролей**, без рискованной перестановки крупных файлов ради одной только эстетики дерева.
