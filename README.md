# ГСМ Ведомости Desktop v1.4.2

Desktop-приложение для расчётных ведомостей ГСМ. React 18 + Vite + Tailwind CSS + Electron 22. Целевая runtime-платформа — **Windows 7 x86 (32-bit)**; приложение также рассчитано на более новые Windows.

## Что изменено в v1.4.2


Новые изменения v1.4.2:

- добавлено создание пользовательских машин прямо из раздела «Автомобили»;
- при создании машины выбирается единица нормы: `л/100 км` или `л/моточас`;
- выбор `л/моточас` автоматически включает учёт моточасов;
- для машин с моточасами путёвка теперь хранит показания **до**, **после** и автоматически вычисляет **отработано**, аналогично одометру;
- конечные моточасы переносятся в следующую путёвку и следующий период, если известны;
- старые записи с единственным полем «отработано моточасов» продолжают читаться без потери данных;
- пользовательские машины участвуют в периодах, истории, Excel-импорте/экспорте и универсальном `.gsmbackup`;
- схема данных повышена до `7`; миграция со схемы `6` автоматическая и обратимо сохраняет старые данные.

Стабилизационные исправления v1.4.1 также входят в эту версию:

- защищена база от тихого сброса при повреждении/ошибке чтения;
- сохранение переведено на безопасную схему temp → fsync → rotation → replace с rollback;
- перед закрытием выполняется синхронный flush последних изменений;
- запрещён параллельный запуск двух экземпляров, работающих с одной базой;
- ошибки автосохранения теперь видимы пользователю и попадают в диагностический лог;
- исправлен пользовательский допуск `0` — он больше не превращается в `0.05`;
- старые/импортированные путёвки нормализуются по хронологии перед переносом остатков;
- для спецмашины с моточасами пустое значение больше не считается настоящим нулём;
- усилена валидация дат, одометра, ГСМ и переноса остатков;
- XLSX защищён лимитами для 32-битной памяти, CRC-проверкой и отклонением encrypted/corrupt ZIP;
- импорт одной книги блокируется, если распознанные листы относятся к разным расчётным периодам;
- тяжёлые import/export/print операции не запускаются одновременно повторными кликами;
- модальные окна получили focus trap и видимый keyboard focus;
- минимальный размер Electron-окна снижен до 800×560 для корректной работы при Windows DPI scaling;
- добавлен стабильный универсальный формат резервной копии `*.gsmbackup`;
- восстановлен regression-набор критической расчётной и файловой логики.

## Runtime и совместимость

Зафиксированные ключевые версии:

- React `18.3.1`;
- Vite `5.4.21`;
- Tailwind CSS `3.4.17`;
- Electron `22.3.27`;
- Vite browser target `chrome108`;
- Windows package target `portable --ia32`.

Electron 22 оставлен намеренно: это последняя основная ветка Electron с поддержкой Windows 7/8/8.1. Не обновляйте Electron/Chromium автоматически — более новые основные версии ломают обязательную совместимость с Windows 7.

> Electron 22 уже находится вне upstream security support. Для этой офлайн/локальной утилиты риск дополнительно снижен: `nodeIntegration` выключен, `contextIsolation` и sandbox включены, внешняя навигация/popups/webview блокируются. Полностью устранить риск EOL-runtime без отказа от Windows 7 невозможно.

## Сборка

Для воспроизводимой сборки используйте lock-файл:

```bat
npm ci
npm test
npm run dist:win7:x86
```

Результат:

```text
release/GSM-Vedomosti-1.4.2-portable-Win7-ia32.exe
```

Собирать пакет удобнее на современной Windows с установленным Node/npm. Получаемый Electron runtime остаётся Electron 22 x86 и предназначен для запуска на Windows 7 x86.

Есть готовый сценарий `VERIFY_RELEASE.bat`, который очищает старые артефакты, ставит зависимости через `npm ci`, запускает regression-тесты, production build, создаёт Win7 x86 portable и проверяет PE-заголовок результирующего EXE.

## Regression tests

```bat
npm test
```

Тесты защищают в первую очередь поведение, влияющее на ведомость или пользовательские данные: расчёт баланса, нулевой допуск, перенос остатков, сортировку путёвок, моточасы, валидацию, atomic-save/recovery/rollback, универсальные backup, CRC/ZIP и согласованность периода при XLSX-импорте.

## Универсальная резервная копия

Основной формат резервной копии — `*.gsmbackup`.

Контейнер имеет собственную стабильную версию `backupFormatVersion`, которая **не привязана к версии приложения**. Версия модели пользовательских данных хранится отдельно как `dataSchemaVersion`. Поэтому последующие версии программы должны продолжать читать `backupFormatVersion: 1`, а более старые схемы данных переводить через обычную миграцию.

В резервной копии также находятся:

- версия приложения, создавшего копию;
- дата создания;
- версия схемы данных;
- SHA-256 контрольная сумма;
- сами пользовательские данные.

Повреждённая/изменённая копия отклоняется. Импорт прежних `.toml` и `.json` сохранён, но legacy JSON проходит строгую проверку структуры. Более новая схема данных не восстанавливается в старую программу молча.

**Политика совместимости:** `backupFormatVersion` не менять и существующие `.gsmbackup` не ломать без отдельного решения пользователя и явного плана миграции. Необратимые изменения обсуждаются до реализации.

## Хранение и восстановление базы

Основная база хранится в профиле Electron как `gsm-data.json`. Во время безопасного сохранения используются временный файл и `.bak`. Если основной JSON повреждён, приложение пытается восстановить валидную более новую временную запись или backup. Если ни один вариант нельзя доверенно открыть, автоматическое сохранение блокируется и показывается recovery-screen — пустая база не должна молча перезаписать существующие данные.

Диагностические ошибки пишутся в ограниченный по размеру `gsm-errors.log` с одной ротацией `.previous`.

## Performance profile

Режим слабого ПК включён по умолчанию:

- отключаются тяжёлые blur/shadow/transition эффекты;
- большие списки монтируются постепенно во время idle;
- сводные расчёты кешируются пока объект состояния не изменился;
- formatter/index объекты переиспользуются;
- Excel/template engine загружается лениво;
- импорт XLSX ограничен по входному и распакованному объёму для защиты 32-bit процесса;
- операции записи сериализуются, а устаревшие ожидающие autosave пропускаются;
- данные JSON сохраняются компактно.

## Ограничения проверки

Исходник содержит автоматические regression-тесты и release-скрипт, однако окончательный релиз считается подтверждённым только после успешного выполнения `VERIFY_RELEASE.bat` и ручного smoke/UI прохода собранного `ia32` EXE, желательно в реальной Windows 7 x86 VM/машине и на нескольких разрешениях/DPI.
