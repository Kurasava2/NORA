# ГСМ Ведомости Desktop v1.5.1

Desktop-приложение для расчётных ведомостей ГСМ. React 18 + Vite + Tailwind CSS + Electron 22, целевая система — Windows 7 x86 (32-bit).


## v1.5.1 — границы модальных окон

- все модальные окна ограничены рабочей областью приложения под titlebar и больше не могут выходить за верхнюю/нижнюю границу окна;
- между titlebar и модальным окном всегда сохраняется визуальный отступ, как и от боковых/нижней границ;
- широкие и extra-wide модалки ограничиваются шириной доступной области;
- длинные формы (`Автомобиль`, `Путёвка`, `Настройки` и другие) используют внутреннюю прокрутку содержимого, при этом шапка и кнопки действий остаются внутри модалки;
- на низких и узких окнах отступы адаптивно уменьшаются, но модалка всё равно не пересекает titlebar;
- схема данных и формат `.gsmbackup` не менялись.

## v1.5.0 — автоматический расчёт расхода

- список периодов убран из левой панели: периоды открываются из «Обзора периодов», без дублирования навигации;
- исправлен лишний JSX-хвост `/>}` в пустом состоянии обзора периодов;
- у каждой машины появился безопасный конструктор автоматического расчёта расхода;
- формулы поддерживают пробег (`КМ`), моточасы (`МОТОЧАСЫ`), основную норму (`НОРМА`), собственные параметры машины и результаты других расчётных правил;
- формулы вычисляются собственным парсером без `eval()`; ошибки синтаксиса, деление на ноль и циклические зависимости блокируются;
- одно правило может объединять несколько фактических материалов (например ДТ «А» + ДТ «З») в один нормативный расход;
- стратегия «Минимизировать количество остатков» старается полностью обнулить один из видов топлива, чтобы в следующую путёвку переносился один остаток;
- также доступны приоритетное и пропорциональное списание либо режим «только рассчитать общий расход»;
- перед применением показывается предпросмотр расчёта, а недостаток остатка блокирует автоматическое применение;
- автоматические значения можно исправить вручную; они помечаются `AUTO`, после ручной правки — `MANUAL`;
- при изменении пробега, моточасов, входных параметров или начальных остатков приложение сообщает, что AUTO-расчёт устарел;
- схема данных повышена до 9, формат `.gsmbackup` остаётся прежним (`backupFormatVersion: 1`).

## v1.4.2 — моточасы как счётчик и нормы л/моточас

- базой является успешная UI/refactor-линия v1.4.1, без отката интерфейса к старому монолитному варианту;
- для машин с учётом моточасов путёвка хранит показания **до / после**, а «отработано» считается как разница;
- конечные моточасы предыдущего периода переносятся как начальное показание следующего;
- старые записи, где было только одно значение «отработано моточасов», продолжают читаться без потери данных;
- в карточке автомобиля выбирается тип нормы: **л/100 км** или **л/моточас**;
- для нормы `л/моточас` учёт моточасов включается автоматически;
- в специальном XLSX-листе показания моточасов записываются в существующие колонки E/G, а отработано — в существующую итоговую колонку;
- схема данных повышена до 8; контейнер `.gsmbackup` остаётся `backupFormatVersion: 1`;
- старые TOML/JSON форматы резервной копии по-прежнему намеренно не поддерживаются.

## v1.4.1 — корректировки рабочего интерфейса и импорта

- расчётные периоды отображаются вертикальными строками внутри сворачиваемых секций годов;
- русские окончания числовых подписей формируются по количеству;
- импорт месячной Excel-книги учитывает только путёвки, даты которых входят в период из шапки книги; старые строки предыдущих месяцев не делают автомобиль «ездившим»;
- в итоговых строках ГСМ нулевые итоговые значения выводятся как `0`, но нули по последующим путёвкам по-прежнему не протягиваются;
- сервисные команды переименованы в «Сохранить», «Сделать резервную копию», «Восстановить из копии»;
- в форме путёвки подпись «Пройдено» вынесена над полем значения;
- формат `.gsmbackup` и схема пользовательских данных не менялись.

## v1.4.0 — полный UI redesign

Интерфейс полностью обновлён по дизайн-языку пользовательского проекта `ep-modpack-updater`:

## Performance profile v1.4.1

- Low-end PC mode enabled by default: blur/backdrop-filter, large shadows and transition-heavy effects are disabled.
- Fleet/month tables mount progressively during browser idle time instead of blocking one frame with all rows.
- Expensive fleet summaries are cached while the state object is unchanged.
- Number/date formatters and vehicle/catalog indexes are reused instead of rebuilt per cell.
- Navigation uses React transitions and search uses deferred values.
- Autosave is scheduled in browser idle time.
- Excel/template engine is code-split and loaded only for import/export/template inspection.
- State mutations no longer run a second full migration/deep clone after every change.
- Electron disables spellcheck and uses compact JSON persistence.

## Универсальная резервная копия

Начиная с этой ревизии приложение экспортирует один стабильный формат резервной копии: `*.gsmbackup`.

Формат контейнера резервной копии имеет собственную версию (`backupFormatVersion`) и **не привязан к версии приложения**. Версия структуры пользовательских данных хранится отдельно (`dataSchemaVersion`). Поэтому последующие версии приложения должны продолжать читать `backupFormatVersion: 1`, а данные более старых схем переводить штатной миграцией `migrateState`.

В файл также записываются версия приложения, время создания и SHA-256 контрольная сумма данных. Повреждённая или изменённая копия не восстанавливается молча.

Импорт прежних `.toml` и `.json` копий намеренно не поддерживается. Начиная с v1.4.0 приложение работает только с `.gsmbackup`. Старая рабочая копия пользователя была отдельно разово конвертирована в новый формат. Новая резервная копия, созданная версией приложения с более новой схемой данных, не должна восстанавливаться в старую программу автоматически: пользователю предлагается сначала обновить приложение.

**Политика совместимости:** не менять `backupFormatVersion` и не ломать чтение существующих `.gsmbackup` без отдельного решения и явной миграции. Если в будущем потребуется действительно необратимое изменение формата или модели данных, оно рассматривается отдельно до реализации.
