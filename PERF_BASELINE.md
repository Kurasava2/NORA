# Performance baseline — v1.4.2 source

Эти числа — **не benchmark целевой Windows 7 машины**. Они измерены в текущей Linux/Node 22 среде и нужны только как контроль масштаба чистой логики/JSON persistence. React/Chromium DOM, x86 Electron memory и HDD на Win7 должны измеряться отдельно на собранном приложении.

Синтетическая ведомость: одна машина, один материал, заполненные одометр/ГСМ, 10/100/500/1000 путёвок.

| Путёвок | Полная базовая validation, ms | 100 `smartBalance`, ms | Atomic JSON save + fsync, ms | Размер JSON |
|---:|---:|---:|---:|---:|
| 10 | 0.033 | 0.037 | 0.561 | 2.5 KB |
| 100 | 0.230 | 0.159 | 1.925 | 22.8 KB |
| 500 | 0.742 | 0.085 | 2.114 | 114.1 KB |
| 1000 | 0.918 | 0.085 | 4.715 | 228.4 KB |

Вывод: чистая арифметика и сериализация базы не являются главным bottleneck при реалистичных месячных объёмах. Приоритет profiling на целевой машине остаётся за DOM/render таблиц, Chromium working set и XLSX import/export/print.
