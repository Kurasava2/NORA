# Работа через Obsidian и GitHub

## Модель

Приватный GitHub-репозиторий хранит рабочий vault. Obsidian открывает корень клонированного репозитория как хранилище. Редактор и помощник работают с теми же Markdown-файлами через Git, поэтому библиотека чата не является основным местом проекта.

## Ветки

- `main` — проверенное текущее состояние.
- Для крупного литературного пакета допустима временная ветка вида `работа/главы-19-24`; после проверки она сливается в `main`.
- Малые безопасные правки можно делать непосредственно в `main`, если перед началом выполнено обновление репозитория.

## Обычный цикл

1. Получить последние изменения.
2. Открыть vault в Obsidian.
3. Работать с отдельными заметками и главами.
4. Запустить проверку проекта.
5. Просмотреть список изменённых файлов.
6. Сделать коммит с понятным русским сообщением и отправить его в приватный репозиторий.

## Телефон

На Android локальная папка репозитория открывается в Obsidian как vault. Git можно обслуживать через Termux или проверенный мобильный способ синхронизации. Токен доступа не хранится в заметках, настройках vault или файлах репозитория.

## Исходные архивы

Большие исходные ZIP не коммитятся. Они хранятся отдельно как приватные материалы выпуска; их имена и SHA-256 находятся в [[../98 Источники/Реестр исходников|реестре исходников]].
